# Автономная игра: правила и проверка обновления

Облачная база проверки: `3e16f2bc355689398351e75bad00de732d171f20`.
Основная локальная папка и её незакоммиченные изменения не изменяются.

## Рейд

| Аккаунт | ID героя | Роль | Старт |
|---|---|---|---|
| keis | 905853 | медик | единственный руководитель |
| firewhite | 31389504 | воин | ожидает руководителя |
| ok / vagojan | 1286381 | воин | через ОК, ожидает руководителя |

Общий таймер основан на Unix time: сбор начинается каждые 30 минут,
на протяжении первых 10 минут интервала. Это одинаковые окна :00–:10 и
:30–:40 для всех процессов, независимо от времени их запуска.
Игровой зал служит общим источником готовности. Руководитель проверяет
ID, класс и готовность каждого из трёх; посторонний игрок не заменяет
отсутствующего участника. Списки по одному числу готовых больше не используются.

Состояние попытки сохраняется до отправки старта. При возобновлении процесса
бой обслуживается раньше любых хозяйственных переходов. Отсутствие кнопок
или исчерпание локального лимита ходов не вызывает выхода из рейда.
Неоднозначный результат остаётся неоднозначным: победа не предполагается.
После 10 минут без боевой панели восстановление закрывается с неподтверждённым
результатом. История последних 20 попыток хранится в `state/<account>/runtime.json`.
Наблюдаемые урон и лечение — нижняя оценка по доступным строкам журнала:
одинаковые строки, повторные загрузки и неполный серверный журнал ограничивают точность.
HP цели не подменяется единственным значением HP самого героя.

Ограничение: проверка состава и нажатие старта — два разных серверных действия.
Игра не предоставляет атомарную блокировку состава; участник может потерять
сессию между ними. Нужна проверка реального совместного боя, прежде чем
решать, достаточно ли трёх героев.

## Башни, инвентарь и экономика

- Любая ненулевая или неизвестная усталость запрещает вход в башни.
  Непосредственно перед входом значение читается снова; фоновые входы
  используют тот же барьер. Сохранённая пауза не разрешает вход без свежего нуля.
- Автоматическое надевание отключено на границе драйвера, в том числе после
  почты и магазина. Мифические вещи нельзя разобрать или отправить на витрину.
  Массовый разбор без проверки каждой вещи отключён.
- Свитки выбрасываются; книги и неизвестные предметы не активируются.
  Распознанные сундуки с явной бесплатной кнопкой открытия обрабатываются
  при уборке инвентаря; неизвестные и платные подтверждения пропускаются.
- Алтарь обслуживается железом. Дополнительные бои, опыт и сброс усталости
  за золото запрещены. Оплачиваемый игровой LLM-советник отключён.
- Железо разрешено покупать только при известной необходимости ремонта,
  нулевом остатке железа и известной стоимости ремонта. Лимит одной операции
  и суток — 1 золото; дополнительно не более 50 серебра за предложение.
  Курс серебра к золоту не предполагается. Предпочтительны предложения
  без золота. Любая неясность цены/валюты на подтверждении запрещает покупку.
- До покупки резервируется весь дневной лимит. Успех проверяется по изменению
  железа и обеих валют. Неоднозначная отправленная покупка остаётся заблокированной
  даже после смены даты, пока её результат не проверен. Неотправленная или
  подтверждённая операция тоже не повторяется в те же сутки.
- В Actions резерв записывается немедленно в отдельный файл через GitHub Contents
  API с проверкой SHA. Без токена, при конфликте или сетевой ошибке покупка запрещена.
  Файл не перезаписывается итоговым коммитом дневных счётчиков.
  Локально используются атомарная запись и эксклюзивный файл блокировки.
- Дни бюджета считаются по UTC+3. При двух независимых локальных копиях одного
  аккаунта без общего состояния общий лимит не гарантируется: для игры должен
  работать один агент на аккаунт. Actions обеспечивают это группой concurrency.

## Безопасные проверки и ввод в эксплуатацию

```sh
python -m compileall -q barbars run.py
python -m pytest tests/test_safety_offline.py -q
```

`pytest.ini` ограничивает обычный сбор офлайн-набором: остальные файлы `tests`
содержат живые пробы и не должны запускаться общей командой.
Набор подменяет сетевой доступ; игровые сессии и браузеры не используются.
Workflow `offline-safety-tests` выполняет эти проверки без игровых секретов.

После проверки ветки облачное обновление должно переходить на новые файлы
после завершения текущих сеансов. Их отмена и параллельный запуск второй
сессии одного героя для обновления не нужны. `agent-vagojan` остаётся без cron.
Фактический переход проверяется по `head_sha` следующих трёх workflows.
Результат рейда подтверждается составом, действиями каждого героя,
оставшимся HP и итогом попытки, а не только зелёным статусом GitHub Actions.

Изменения разработаны Codex. Успешных вызовов Router Chip в этой среде не было.

Пути трёх облачных конфигов явно считаются от корня репозитория
(`paths_relative_to: repository`). Это исключает ошибочную запись счётчиков
и журналов в `deploy/state` и `deploy/logs`, которые workflows не сохраняли.
Проверка использует настоящий `run.load_config`, а не только подменённый корень теста.
