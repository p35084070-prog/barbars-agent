# Перенос аккаунта ОК в облако (GitHub Actions)

## Коротко

**Да, перенести можно.** Проверено на практике: сессия ОК — это несколько
cookie (около 700 байт в base64+gzip), которые помещаются в GitHub Secret.
На чистом раннере, восстановив сессию из секрета, игра открывается и в неё
можно играть — этим занимается тот же агент, что и на обычном `barbars.ru`.

## Как это устроено

Игра «Варвары» в каталоге ОК (appId=128512) — мобильное приложение.
На `ok.ru` в десктопе её нет (`mob_only_app`). Но мобильная версия сайта
`m.ok.ru/app/barbars` ведёт себя иначе: с авторизованной сессией игра
открывается в iframe на `od.barbars.ru` и получает подписанные параметры
запуска ОК (`logged_user_id`, `session_key`, `auth_sig`, `api_server=https://api.ok.ru/`).

Особенности канала ОК, из-за которых нужен отдельный адаптер:

| Что | Почему |
|---|---|
| игра в iframe, а не на верхнем уровне | драйверу отдаётся «страница»-адаптер над кадром |
| сессия игры в `;jsessionid=` в URL | обычная навигация без него уводит на `/authorization` |
| ссылки относительные | адаптер строит URL от корня сайта, как обычный `Game` на barbars.ru |
| ОК пересоздаёт игровой iframe | кадр ищется заново при каждом обращении, клик делается с повтором |

## Что уже проверено в канале ОК

Прогон агента через ОК (`run.py --config config-ok.json play-ok --headless`)
делает всё то же, что и на `barbars.ru`:

- читает состояние героя (уровень, класс, HP/энергия, золото/серебро/железо, опыт);
- забирает бесплатный подарок колодца удачи;
- тратит очки талантов («Сила воли»);
- ходит в бои (подземелья, дуэли), применяет умения и бьёт — бесплатные бои
  расходуются, растёт участие и опыт;
- переходит по страницам `/user/stances`, `/game/towers`, `/trade/well`,
  `/user/rack`, `/user/body/id/...` и другим (7 из 7 открылись с первого раза).

## Подготовка (один раз, на ПК)

1. Войти в ОК:

   ```powershell
   python tools\ok_phone.py
   ```

   Откроется окно браузера с мобильной экранизацией ОК. Войдите руками.
   Сессия сохранится в `profile-ok-phone` (кука `domain_sid`).

2. Выгрузить сессию:

   ```powershell
   python tools\ok_export_cookies.py
   ```

   Появятся `state/ok-session.json` и `state/ok-session.b64` (~700 байт).
   Эти файлы — **живой доступ к аккаунту**, они добавлены в `.gitignore`
   и в репозиторий попасть не должны.

3. Положить содержимое `state/ok-session.b64` в секрет GitHub:

   ```powershell
   gh secret set OK_SESSION_B64 < state\ok-session.b64 --repo <владелец>/<репозиторий>
   ```

## Запуск в облаке

Workflow уже добавлен: `.github/workflows/agent-ok.yml`.

```powershell
# запустить вручную на 30 минут
gh workflow run agent-ok.yml -f duration=30 --repo <владелец>/<репозиторий>

# посмотреть логи
gh run list --repo <владелец>/<репозиторий>
```

Внутри job делается ровно то же, что и локально:

```bash
python -u run.py --config config-ok.json play-ok --headless --duration 330
```

Секрет подставляется через переменную окружения `OK_SESSION_B64`, которую
читает `barbars/ok_channel.py`.

## Локальный запуск

```powershell
python run.py --config config-ok.json play-ok --iterations 5
```

Сессия берётся из `state/ok-session.b64` (путь в `config-ok.json` →
`ok_channel.session_file`) либо из переменной `OK_SESSION_B64`.

## Что важно знать

**Сессия протухает.** ОК ротирует `domain_sid`, и при активном использовании
сессия может слететь (заметно: сессия в профиле исчезает, а сайт
перестаёт отдавать `od.barbars.ru`). Признак в логах CI:

```
[ОК] ждём кадр игры (28/30)...
[ОК] не удалось открыть игру: Игра через ОК не загрузилась
```

Лечение: на ПК заново войти в ОК (`tools\ok_phone.py`), перевыгрузить сессию
(`tools\ok_export_cookies.py`) и обновить секрет:

```powershell
python tools\ok_export_cookies.py
gh secret set OK_SESSION_B64 < state\ok-session.b64 --repo <владелец>/<репозиторий>
```

**Нельзя гонять одну сессию в двух местах одновременно.** Если на ПК открыт
браузер с той же сессией, а CI использует её же — сессии выбивают друг друга
(проверено: `domain_sid` исчезал после параллельных прогонов).
Перед запуском в облаке закрывайте браузер с профилем `profile-ok-phone`.

**ОК троттлит частые входы.** Несколько handshake'ов подряд с одного IP
могут не дать кадр — поэтому в коде ожидание до 30 попыток по 5 секунд.

**GitHub Actions идёт с IP дата-центра.** Для ОК это нормально, но при
большом числе запусков возможны блокировки; при сбоях — пауза между
запусками (в workflow стоит cron раз в 6 часов).

## Файлы

| Файл | Назначение |
|---|---|
| `barbars/ok_channel.py` | адаптер канала ОК: handshake, поиск кадра, «страница» для драйвера |
| `run.py` (команда `play-ok`) | запуск агента через канал ОК |
| `config-ok.json` | конфиг агента для канала ОК (фарм выключен — сначала проверка) |
| `tools/ok_export_cookies.py` | выгрузка сессии ОК в файл/секрет |
| `tools/ok_phone.py` | мобильная эмуляция ОК: вход руками + разведка |
| `tools/ok_play.py` | запуск игры через ОК на ПК |
| `tools/ok_cloud_play.py` | запуск игры через ОК в «облачном» режиме (чистый профиль) |
| `.github/workflows/agent-ok.yml` | CI-задача с секретом `OK_SESSION_B64` |
