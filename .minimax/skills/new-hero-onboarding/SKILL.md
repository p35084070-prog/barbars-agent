# Новый герой: от регистрации до экипировки

Рабочая репозитория: `C:\Users\Богдан\Documents\Богдан MINIMAX\barbars-agent`
(remote `p35084070-prog/barbars-agent`, ветка `main`). Всё в облаке — локальный IP
провайдера не проходит воронку регистрации, поэтому локальные запуски бесполезны.

## Inputs to collect

- **ник** (2–16 символов, ≤2 пробелов) и **логическое имя аккаунта** (латиница,
  `steelblue`, `emberfox`): от него зависят `state/<аккаунт>/`, `credentials-<аккаунт>.txt`,
  `deploy/config-actions-<аккаунт>.json`, имя workflow агента.
- **класс** (`1` — воин, `2` — медик) и **сторона** (`1` — север, `2` — юг).
- **лимит золота на вещь** и **плательщик** (обычно keis — самый богатый).
- **ID получателя** (id героя в игре, не ник) — нужен для отправки почтой.

Если ник/класс/сторона не заданы — спроси; остальное можно взять из существующей
конфигурации `deploy/config-actions-firewhite.json` как образца.

## Procedure

1. **Регистрация в облаке.** Локально воронка нового игрока перекрыта (IP не ротируется),
   поэтому регистрируемся с раннера GitHub:
   ```powershell
   cd "C:\Users\Богдан\Documents\Богдан MINIMAX\barbars-agent"
   gh workflow run register-hero.yml -R p35084070-prog/barbars-agent --ref main `
     -f account=<аккаунт> -f nick="<ник>" -f kind=1 -f side=1
   ```
   Скрипт сам терпеливо опрашивает воронку, заполняет форму (`login`, `sex`, `side`,
   `type`) и **сам ставит пароль** на странице «Защита аккаунта» (`/user/protection/0/1`),
   если пароль не задан явно. Пароль генерируется автоматически (≥6 символов, буквы+цифры).
   Результат: `state/<аккаунт>/credentials.json` в репозитории + артефакт прогона.
   Локально воронку можно проверить, но не пройти: `tools/probe_registration_form.py`.

2. **Забрать пароль в GitHub Secrets.** Креды лежат в артефакте прогона
   (`registration-<аккаунт>-<номер>`), в репозиторий они **не коммитятся** — иначе
   пароль навсегда останется в истории git:
   ```powershell
   gh secret set BARBARS_<АККАУНТ>_LOGIN -R p35084070-prog/barbars-agent
   gh secret set BARBARS_<АККАУНТ>_PASSWORD -R p35084070-prog/barbars-agent
   ```
   Значения пароля нигде не публикуй: в логах и ответах показывай только ник и id.
   Если пароль уже попал в историю git — сначала смени его в игре
   (`change-password.yml`), потом чисти репозиторий.

3. **Проверить вход и пройти туториал.** Вход по нику/паролю открывает страницу туториала
   («Долина варваров»): демо-бой «Сразиться!», затем «Покинуть бой». Клики должны быть
   настоящие (Wicket обрабатывает их на сервере), поэтому это делается браузером:
   ```powershell
   python tools\finish_tutorial_browser.py "<ник>" "<пароль>"
   python tools\check_login.py "<ник>" "<пароль>"
   ```
   После туториала у героя 2 уровень и доступна главная страница.

4. **Узнать id героя** — он виден в ссылках профиля (`user/achivements/id/<id>`,
   `user/body/id/<id>`). Он нужен для отправки почтой.

5. **Подключить агента.** Скопировать `deploy/config-actions-firewhite.json` в
   `deploy/config-actions-<аккаунт>.json` и заменить:
   `account`, `profile_dir`, `state_dir`, `daily_file`,
   `auth.credentials_file` → `credentials/<аккаунт>.txt`,
   `gear.auto_equip` → `true` (только новому герою; у остальных экипировка ручная),
   `raid.enabled` → `false`, `spend.clan_donate.enabled` → `false`,
   `altar.enabled` → `false`, `shop.enabled` → `false`.
   Затем скопировать `.github/workflows/agent-steelblue.yml` в `agent-<аккаунт>.yml`
   и заменить `steelblue` на `<аккаунт>` (имя workflow, группа concurrency, конфиг,
   путь дневных счётчиков, секреты). Прогон 330 мин, cron `*/20`, самоперезапуск.
   Вступление в клан (с 11 уровня) делает `tests/clan_join_auto.py` — там зашит ник,
   поменяй его на ник нового героя.

6. **Закупить снаряжение 25 уровня глазами keis** (у него золото; новый герой богатством
   не владеет). Цены в магазине **серебряные**, а золото игра сама конвертирует
   по курсу 1 золото = 100 серебра, поэтому лимит «не дороже 1 золота за вещь» —
   это ≤ 100 серебра на вещь:
   - сначала снять актуальный каталог (id товаров в магазине **ротируются**):
     ```powershell
     gh workflow run probe-funding2.yml -R p35084070-prog/barbars-agent --ref main -f hero=keis
     ```
   - затем купить отобранные id с жёстким лимитом:
     ```powershell
     gh workflow run buy-gear.yml -R p35084070-prog/barbars-agent --ref main `
       -f item_id=<id1>,<id2> -f max_gold=1
     ```
   - цена читается со страницы товара по иконкам валют (`pages.parse_shop_price_html`):
     «Купить за 6 30» = 6 зол 30 сер, а не 6 сер.
   - перед покупкой проверь на странице товара, что он **25 уровня**: в наборе Ветерана
     встречаются вещи 21–24 ур., а герой 25 ур. надеть их сможет, но это не то,
     что нужно. Уровень товара виден на странице: `<span>25</span> уровень`.
   - каталожный id (`40121857`) и id купленной вещи в рюкзаке (`2093943869`) — разные
   числа; для отправки почтой берём id из рюкзака.

7. **Передать вещи почтой и одеть.**
   ```powershell
   gh workflow run gear-transfer.yml -R p35084070-prog/barbars-agent --ref main `
     -f send_to=<id_героя> -f item_ids=<id1>,<id2>
   gh workflow run equip-hero.yml -R p35084070-prog/barbars-agent --ref main `
     -f account=<аккаунт> -f hero_id=<id_героя> -f equip=true
   ```
   `equip-hero.yml` висит на cron `17 */2 * * *` и сам дотянется, когда герой дойдёт
   до нужного уровня.

## Output contract

Отчёт пользователю (по-русски) содержит:
- ник, id, класс, сторона, текущий уровень;
- что куплено: список вещей с ценой каждой в серебре и золоте, **общая сумма** и
  проверка лимита «не дороже N золота за вещь»;
- что уже сделано (отправлено, лежит в рюкзаке) и что упирается в игру (уровень героя);
- явно отмеченные решения, которые остались за игроком (например, амулет дороже лимита).

## Failure handling

- **Воронка не открылась** — прогоны идут по 120 попыток; если форма не появилась,
  перезапусти `register-hero.yml` (IP раннера каждый раз разный). Локально не получится.
- **Пароль не задан** — форма регистрации пароля не содержит; страницу «Защита аккаунта»
  досылает `tools/finish_registration.py <session.json> <пароль>` (cookies берутся из
  артефакта `registration-<аккаунт>-session.json`).
- **Посылки не забираются кнопкой «ЗАБРАТЬ ВСЕ ИЗ ПОЧТЫ»** — это кнопка только для денег.
  Каждую посылку с вещью надо открыть (`/user/mail/message/id/<id>`) и нажать
  «ЗАБРАТЬ ИЗ ПОЧТЫ» (`getLink`). Это уже делает `tools/equip_hero.py`.
- **Посылка не влезает в рюкзак** — сначала освободить рюкзак (`stash_items` → `crack_items`),
  потом забирать. Рюкзак 20 слотов, сундук ещё 20.
- **«Ты не можешь надеть эту вещь, требуется 25 уровень»** — ограничение игры, не ошибка.
  Вещи остаются в рюкзаке, cron их наденет. Ускорить прокачку за золото нельзя
  («Мудрец» работает только за золото, а золото не тратим).
- **Цена не прочиталась** — покупку вслепую не делаем: цена обязана быть проверена на
  странице товара, иначе лимит по золоту может проскочить.

## Правила, которые нельзя нарушать

- Золото не тратится, кроме явно разрешённой покупки снаряжения в заданном лимите.
- Продаём только ресурсы; дубли вещей не трогаем; мифические/легендарные/эпические не ломаем.
- Мифрил не пересылаем. Железо не продаём (решение игрока).
- В хранилище клана ничего не вливаем; алтарь пополняет только keis и только железом.
- Секреты — только в GitHub Secrets, значения не публикуем; `state/*/credentials.json`
  в репозитории не оставляем.

## Examples

Вход: «создай шестого героя по образцу fire white ii, купи ему комплект 25 уровня
не дороже одного золота за вещь и одень».

Выход: регистрация через `register-hero.yml`, пароль в Secrets, конфиг + агент,
каталог магазина → покупка на ≤100 серебра на вещь → `gear-transfer.yml` →
`equip-hero.yml`; отчёт со списком вещей, суммой и статусом «ждёт 25 уровня».

Детали команд и цифры — в `references/pipeline.md`, правила игры и ловушки — в
`references/game-facts.md`.

## Windows (win32) platform notes

- Рабочая папка содержит кириллицу: `cd` только в кавычках.
- `python`, не `python3`; PowerShell 5.1 не понимает `&&` — команды выполняй по одной.
- Push может упасть по DNS или «non-fast-forward» — повторяй push, при отказе сначала
  `git stash push -- state/keis/daily.json`, затем `git pull --rebase origin main` и push.
- Логи прогонов читаются так:
  ```powershell
  gh run view <run_id> -R p35084070-prog/barbars-agent --log
  gh run list -R p35084070-prog/barbars-agent --limit 10
  ```
  В выводе GitHub имена героев маскируются как `***`, а часть JSON-строк обрезается —
  печатай нужные поля через `python -c`, а не целиком.
