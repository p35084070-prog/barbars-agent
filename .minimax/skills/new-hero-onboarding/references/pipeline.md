# Пайплайн по шагам — цифры и команды (замер 15–16.11.2026)

Это разбор реального прогона «пятого героя» (Steel Blue ii, id 31390082, воин, север).
Цифры — фактические замеры, а не примеры.

## 1. Форма регистрации

Поля: `login` (ник), `sex` (`m`/`f`), `side` (`1` север / `2` юг), `type`
(`1` воин / `2` медик). Пароля в форме нет — игра отдельно открывает
`/user/protection/0/1` с полями `password` / `password2`
(требование: не менее 6 символов, буквы + цифры).

`tools/register_hero.py` умеет и опрос воронки, и досылку пароля на страницу защиты
(функция `set_password`).

## 2. Почему регистрация идёт из облака

Новому игроку показывается «Долина варваров», а форма — только из воронки (после боя).
Локально воронка не открывалась: прямой IP `104.28.193.183`, через локальный прокси
`127.0.0.1:10809` — тот же `86.105.211.61` (ротации нет). С раннера GitHub воронка
открылась с первой попытки.

## 3. Регистрация — команда

```powershell
cd "C:\Users\Богдан\Documents\Богдан MINIMAX\barbars-agent"
gh workflow run register-hero.yml -R p35084070-prog/barbars-agent --ref main `
  -f account=steelblue -f nick="Steel Blue ii" -f kind=1 -f side=1
```

Workflow: `tools/register_hero.py` → `state/<аккаунт>/credentials.json` (ник, пароль, mail)
+ артефакт с cookies (`registration-<аккаунт>-session.json`) и HTML формы.

После этого пароль кладём в Secrets и **удаляем** `state/<аккаунт>/credentials.json`
из репозитория (иначе он останется в истории git).

## 4. Туториал

Страница туториала: демо-бой «Сразиться!», затем «Покинуть бой». Клики обрабатываются
сервером (Wicket), поэтому только браузер:

```powershell
python tools\finish_tutorial_browser.py "Steel Blue ii" "<пароль>"
python tools\check_login.py "Steel Blue ii" "<пароль>"
```

После туториала: 2 уровень, доступна главная. Дальше — фарм башни агентом.

## 6. Магазин снаряжения — цены и лимиты

* Цена — **серебро**. «Купить за 55» = 55 серебра; «Купить за 6 30» = 6 зол 30 сер.
  Золото игра сама добирает по курсу **1 золото = 100 серебра**
  (проверено: цена 161 сер списалась как 1 зол + 61 сер).
* Лимит «не дороже 1 золота за вещь» = **≤ 100 серебра на вещь**.
* **id товаров в магазине ротируются**: список в 22:19 и список в 22:39 — разные id.
  Каталог снимать заново непосредственно перед покупкой:
  ```powershell
  gh workflow run probe-funding2.yml -R p35084070-prog/barbars-agent --ref main -f hero=keis
  ```

## 7. Передача почтой

Купленная вещь приходит **почтой** получателю («Есть новая почта!»), в рюкзак
попадает только после забора.

```powershell
gh workflow run gear-transfer.yml -R p35084070-prog/barbars-agent --ref main `
  -f send_to=31390082 -f item_ids=2093969236,2093960007,2093944997
```

`tools/gear_transfer.py` отправляет по одной вещи из рюкзака (`send_bag_item_to`),
потому что «Выбрать все» на витрине забрало бы и чужие вещи.

## 8. Забор и экипировка на стороне получателя

```powershell
gh workflow run equip-hero.yml -R p35084070-prog/barbars-agent --ref main `
  -f account=steelblue -f hero_id=31390082 -f equip=true
```

`tools/equip_hero.py`:
1. освобождает рюкзак (`stash_items` → `crack_items`);
2. забирает посылки: каждую открывает (`/user/mail/message/id/<id>`) и жмёт
   «ЗАБРАТЬ ИЗ ПОЧТЫ» (`getLink`);
3. переносит вещи из панели «новый предмет» в рюкзак;
4. надевает мифические вещи (`items:N:wearLink`).

Cron `17 */2 * * *` — пока герой не дорос, вещи просто ждут.

## 9. Ограничения, которые увидели на живых данных

- **Уровень героя важнее уровня вещи**: «Ты не можешь надеть эту вещь, требуется
  25 уровень» (Бурка Ветерана — с 21 уровня). Комплект 25 ур. лежит в рюкзаке
  до 25 уровня героя.
- **Рюкзак ограничивает приём посылок**: пока рюкзак забит дропом, посылка не
  влезает и остаётся в почте.
- **Туториал/квесты в башне**: 12 уровень даёт ~8.6K опыта на уровень — до 25
  уровня идёт обычный фарм башни.
